# Phase 5: Admin Dashboard

Date: 2026-10-10; review corrections completed 2026-10-11. Target project: `gbhleqizxcmxmutgcjon`. The approved Phase 4 baseline is `eabf28f`; this milestone is on `codex/phase-5-admin-dashboard`. Phase 6 room editing is outside this scope.

## Design and data flow

`admin.html` is the Admin entry point. `js/admin/app.mjs` handles the route, navigation, rendering, and account actions; `js/data/admin-repository.mjs` loads the catalog and staff directory. The Product Owner's Phase 5 review required a redesign: the workspace now uses the same near-black surfaces and yellow accent as the Game Master and Cast product, with Arabic as the default language and an RTL layout. The entry route is `?view=rooms`; `room&id=<id>`, `staff`, and `account` remain direct links. Refresh, browser history, and legacy `?view=overview` links (redirected to Rooms) work. The original overview page was removed. Room names are translated for the three existing room IDs in the presentation layer; unknown names fall back to the database name. Room management, staff provisioning, and gameplay session metrics are not represented as live controls until their approved phases.

Room cards, hints, and media come from the existing Supabase rooms, `room_hints`, and `room_media` records through the authenticated catalog repository. The staff page uses the narrow `admin_staff_directory()` RPC. Counts shown on room cards and details are computed from fetched rows. Detail pages show the existing content and locally resolvable media links. Missing images, empty records, loading, and network errors have explicit states. User-supplied database strings are rendered as text; media links are limited to local `images/` and `source/` references. Technical IDs and emails are isolated LTR within the RTL interface. Local Lucide SVG icons represent Rooms, Staff, and Account; their ISC license is stored with the icons.

The second review keeps the existing logo and centers it above `لوحة الإدارة`, removes the workspace label, search, status filter, visible room IDs, and redundant Rooms/Staff page introductions. Screen-reader-only headings preserve the page structure. Room cards and detail views use compact tags computed from each room's records: hints from `room_hints`, images only from `gm_image`, videos only from `lose_video`, and audio from `hint_sound`, `lose_sound`, and `gm_sound`. Room thumbnail/background references are not counted as media records. The 2026-10-10 verified project snapshot has: Prison 50 hints, 1 image, 0 videos, 3 audio; Pyramid 32 hints, 2 images, 0 videos, 1 audio; Uncle Saleh 47 hints, 1 image, 1 video, 1 audio. The current browser still reads live Supabase rows; these numbers are validation evidence, not seeded UI values.

The Admin avatar now uses an Auth display name initial when present, otherwise the email initial, then a neutral symbol. The same initial appears in the sidebar, top bar, and Account card. No profile-image storage or trusted image field exists in the current schema, so an image is not shown or invented. Auth display metadata is presentation-only and does not influence role checks.

The final review corrected the Account screen's older presentation and stale profile state. Its identity card now uses the current compact dark layout and shows the verified Auth email when no display name exists; it no longer invents a generic account name. Navigation to Account waits for `currentAccess()` before presenting profile data, and later Auth changes rerender the account when identity fields change. Account rendering is independent of room and staff catalog reads, so a slow or failed catalog request does not hide the authenticated user's information. Versioned page assets and the imported profile helper address a Chrome module-cache case observed in the live Admin tab. The top bar and document title use each route's own Arabic title, without a Rooms prefix on Staff or Account. Tablet navigation collapses at 950 px so the staff directory remains legible.

The Product Owner supplied five valid Thmanyah Serif Display OpenType binaries in `css/fonts/`: `thmanyahserifdisplay-Light.otf` (300), `thmanyahserifdisplay-Regular.otf` (400), `thmanyahserifdisplay-Medium.otf` (500), `thmanyahserifdisplay-Bold.otf` (700), and `thmanyahserifdisplay-Black.otf` (900). Each has an `OTTO` signature, the corresponding embedded weight, and Arabic glyph coverage. `css/fonts.css` declares them as local `@font-face` sources with `font-display: swap`; both `css/admin.css` and `css/style.css` import those declarations. The family applies to Admin, Login, Recovery, Staff Home, and the shared Game Master/Cast styles. Tahoma, Segoe UI, and Arial remain fallback families. macOS `._*` files remain excluded by `.gitignore`.

Chromium verification at desktop and mobile sizes found `"Thmanyah Serif Display"` in computed styles, all five faces with `status: loaded` after explicitly requesting their weights through `document.fonts.load()`, and an HTTP 200 network response for each `.otf`. Login, Recovery, and Staff Home naturally load Regular and Bold; the other weights remain available on demand. The browser sent no request to an external font service. Localhost preview uses `python -m http.server 8765 --bind 127.0.0.1 --protocol HTTP/1.1` from the repository root.

The Phase 4 Auth guard still determines the user's current role before showing the dashboard. The data boundary remains Supabase: the browser has only the publishable key and authenticated user token. Game Masters and anonymous visitors cannot read the Admin staff directory through the RPC, even by calling the endpoint directly. Gameplay continues to use local state and BroadcastChannel; this milestone does not create or migrate server sessions.

## Database change

[`20261010120931_phase5_admin_staff_directory.sql`](../supabase/migrations/20261010120931_phase5_admin_staff_directory.sql) adds one read-only SQL function. It returns staff email, verification state, role, active state, and assigned room IDs by joining `staff_accounts`, `staff_room_access`, and `auth.users`. A fixed empty search path and fully qualified names protect the `security definer` function. It returns rows only when `ahaji_private.current_staff_role()` recognizes a currently confirmed, active Admin with a live Auth session. `anon` and `public` have no EXECUTE grant; `authenticated` has the grant but gets no rows without the Admin role. Existing table RLS and writes were not changed. No new table, seed record, or Supabase paid service was introduced.

## Backup and recovery

A fresh restricted, Git-ignored snapshot was taken **before** the migration: `backups/phase5-pre-migration-20261010.json` (SHA-256 `A957E5466FB8FEAF802D2EDB9AC21D32F47EC7DC4F5819EFC7C47740896F4646`). It contains 3 rooms, 129 hints, 10 media references, 0 gameplay sessions, 1 staff role, 0 room assignments, and a minimal mapping for 1 Auth identity. After the migration, `backups/phase5-final-20261010.json` was captured and packaged (SHA-256 `81B3385961853214E59BEB5B4DAFA2FFB60BC9AF4358908EBF0EE46893D76481`). The backup script accepts the known Phase 4 or Phase 5 migration sequence and includes the corresponding versioned schema.

The final snapshot was restored into a **separate disposable local PostgreSQL 17 database** named `ahaji_phase5_restore`, without a published network port. A new export from that database matched the live snapshot by row count and per-table SHA-256 for all six application tables. After recreating only the confirmed Auth identity as a local test fixture, a disposable authenticated session read the Admin directory through the restored authorization rules. The live Supabase project was not used as a restore target.

To repeat: run [`export_phase4.sql`](../supabase/backup/export_phase4.sql) through authorized read-only SQL access to this project, save its single `snapshot` JSON value in restricted `backups/`, then run `node scripts/phase4-backup.mjs package backups/<name>.json`. In an empty disposable PostgreSQL 17 database, apply `supabase/tests/phase4_local_bootstrap.sql`, then the packaged `-schema.sql`, `-local-auth-fixture.sql`, and `-restore-data.sql` with `psql -v ON_ERROR_STOP=1`. Export the restored database with the same exporter and run `node scripts/phase4-backup.mjs verify backups/<name>.json backups/<restored>.json`. The local Auth fixture must **never** be applied to hosted Supabase. For a replacement hosted project, follow the Phase 4 verified-email re-invitation and role remapping process before restoring application data.

The snapshot includes personal email addresses and must remain access controlled and outside Git. It does **not** back up managed Auth passwords, tokens, sessions, MFA, or email provider settings. A full disaster recovery plan needs those Supabase-managed capabilities recreated through supported Auth flows. See the [Phase 4 recovery note](AHAJI_PHASE_4_AUTH_RBAC.md) for the identity relationship and limitations.

The Product Owner completed the private password sign-in without sharing credentials. The revised Arabic interface uses the same read-only queries and authorization path.

Desktop, tablet, and mobile captures were reviewed for layout, image fit, navigation, and the Arabic authentication screens. Final test results are recorded in the Phase 5 review delivery.
- Current review: 17 Python Playwright browser tests and 4 Node tests passed, including Account revalidation across navigation, refresh, direct URL, and catalog failure; real Thmanyah font loading on desktop and mobile; desktop/tablet/mobile layouts; and the Phase 2 GM/Cast regression. The signed-in live Admin browser showed the confirmed account email and role after Staff → Account navigation. Local PostgreSQL `phase5_directory_rls.sql` passed Admin, Game Master, forged metadata, expired session, and anonymous EXECUTE checks in the original Phase 5 delivery. A live anonymous RPC request returned HTTP 401; the live function grants and definition were inspected then. This review made no database change. A fresh MCP read was unavailable because the configured connector's OAuth token refresh failed, so current media-kind counts were checked against the verified 2026-10-10 project snapshot rather than claimed as a new live SQL result.
- Existing GM/Cast communication remains local to a browser storage context. Password recovery depends on Supabase Free email delivery limits. The read-only staff page does not invite or edit staff, and no gameplay session analytics exist yet.

## Local review

Open `http://127.0.0.1:8765/admin.html?view=rooms` while signed in with the verified Admin account. The Arabic Rooms page is the landing view. Open each detail and its media; visit **فريق العمل** for roles and assignments; visit **حسابي** for verified email, email-change entry, and password recovery. Use browser back and refresh on a detail route. The Game Master entry remains available in the sidebar. If signed out, the protected Admin route redirects to the Arabic login screen. Only submit an email change if you intend to verify a new inbox.
